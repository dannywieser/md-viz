# api-client

Typed clients for the repo's HTTP APIs, generated by [hey-api](https://heyapi.dev) from each API's OpenAPI spec. Exports TypeScript source, no build step. The generated code is gitignored and built on demand.

## Flow

```
apps/cache/src (zod routes)  --pnpm openapi-->  apps/cache/openapi.json (committed)
                             --pnpm generate-->  packages/api-client/src/generated/cache/ (gitignored)
```

- The server defines its routes and zod schemas (`@hono/zod-openapi`); that is the single source of truth.
- `pnpm openapi` rewrites the committed spec from the routes. A cache test fails when the spec is stale.
- `pnpm generate` turns every spec listed in `openapi-ts.config.ts` into a client. `build`, `typecheck`, `test` and `lint` at the repo root run it first. A workspace script run directly (for example `pnpm --filter @md-viz/web test`) needs `pnpm generate` to have run once on a fresh clone.

## Using the cache client

```ts
import { configureCacheClient, listNotes } from '@md-viz/api-client/cache'
import { listNotesOptions } from '@md-viz/api-client/cache/react-query'

configureCacheClient({ baseUrl: 'http://localhost:8787' })

// plain fetch SDK (usable in Electron main, no React)
const { data } = await listNotes({ query: { fields: 'title,synced' } })

// TanStack Query (React)
const { data: rows } = useQuery(listNotesOptions({ query: { fields: 'title' } }))
```

Every SDK call validates its request and its response with the generated zod schemas (`zNoteRow`, `zUpsertBody`, ...), which the entry also exports. Mutations are `upsertNotesMutation()` and `deleteNoteMutation()`. List rows are `{ id, fields }`.

## Adding an API

1. Give the server a zod OpenAPI spec and a script that writes it next to the server.
2. Add `{ name, spec }` to the `apis` list in `openapi-ts.config.ts`.
3. Add `src/<name>/index.ts` (re-export the generated code and a `configure<Name>Client`) and an `exports` entry in `package.json`.
